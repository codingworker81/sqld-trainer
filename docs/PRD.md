# SQLD 2과목 암기학습 앱 PRD

Oct 24, 2026 · @Andrew

## 1. 개요

2026-11-14(토) SQLD 시험까지 남은 3주 동안, 2과목 SQL 문법(함수·연산자·메타문자 등)을 매일 짧게 반복 암기하게 해 주는 개인용 학습 앱을 만든다. 앱은 1주 안에 MVP를 완성해 나머지 2주를 실제 학습에 쓰는 것을 전제로 설계한다.

### 배경

- SQLD 2과목은 40문항(80점)으로 시험의 대부분을 차지하며, 함수 결과값·NULL 처리·Oracle과 SQL Server 차이처럼 정확히 외워야 맞히는 문항이 많다.
- 학습 가능한 시간은 평일 퇴근 후로 제한되어, 긴 교재 회독보다 10\~30분 단위의 반복 학습이 필요하다.
- 정리된 요약 자료(SQL 문법 18개 단원 + 정규식 메타문자)는 이미 있지만, 읽기만으로는 기억 유지와 취약점 파악이 어렵다.

### 문제 정의

| 문제 | 앱이 제공할 해결책 |
| --- | --- |
| 요약 자료를 읽어도 시험장에서 결과값이 바로 떠오르지 않음 | 쿼리를 보고 결과를 맞히는 능동 회상(Active Recall) 카드 |
| 무엇을 얼마나 외웠는지 모름 | 카드·단원별 숙련도와 D-day 기준 진행률 |
| 틀린 것을 다시 볼 체계가 없음 | 간격 반복(Leitner) 기반 자동 복습 스케줄과 오답노트 |
| 함정 포인트가 여러 단원에 흩어져 있음 | ⚠️ 함정 항목만 모아 보는 함정노트 |

### 제품 목적

요약 자료 전체를 카드로 바꿔, 시험 3일 전까지 모든 카드를 최소 한 번 이상 "맞힘" 상태로 만들고, 마지막 3일은 함정·오답 위주로 집중 복습하게 한다.

## 2. 목표와 성공 지표

최종 목표는 2과목에서 과락(40% 미만) 없이 32문항(64점) 이상을 맞히는 것이며, 앱 지표는 이를 위한 선행 지표로 둔다.

| 지표 | 목표값 | 측정 시점 |
| --- | --- | --- |
| 전체 카드 1회 이상 학습 | 100% | 11/8까지 |
| 전체 숙련도(Box 3 이상 카드 비율) | 80% 이상 | 11/11(D-3)까지 |
| 함정 카드 숙련도 | 90% 이상 | 11/13(D-1)까지 |
| 단원별 모의 퀴즈 정답률 | 모든 단원 80% 이상 | 11/11까지 |
| 학습일 연속 기록 | 평일 하루 20분 이상, 주 5일 이상 | 매주 |
| 앱 MVP 완성 | P0 기능 동작 + 카드 데이터 탑재 | 10/31까지 |

시험 배점은 50문항 100점(1과목 10문항, 2과목 40문항), 합격 60점·과목별 과락 40% 기준으로 가정했으며, 최신 시행 공고로 한 번 확인한다.

## 3. 대상 사용자와 사용 시나리오

사용자는 본인 1명이다. 펌웨어(C) 개발 경력은 있지만 데이터 분야는 비전공이고, 평일 퇴근 후와 주말에만 공부할 수 있는 SQLD 수험생이다.

### 핵심 시나리오

1. **퇴근 후 20분 복습 (평일)**: 홈 화면에서 "오늘 복습 32장"을 누르고 카드를 넘기며 맞힘/틀림을 표시한다. 끝나면 오늘의 정답률과 내일 복습 예정 수를 확인한다.
2. **교재 진도 맞춰 신규 학습 (주말)**: 에듀윌 교재에서 "윈도우 함수"를 읽은 뒤, 앱에서 해당 단원의 요약노트를 보고 신규 카드 학습을 시작한다.
3. **취약 단원 집중 공략**: 통계 화면에서 숙련도가 가장 낮은 "계층형 질의"를 골라 단원 퀴즈 20문항을 푼다.
4. **자투리 시간 함정 점검 (모바일)**: 이동 중 스마트폰으로 함정노트를 열어 ⚠️ 카드만 OX로 빠르게 넘긴다.
5. **시험 직전 총정리 (D-3 \~ D-1)**: 시험 모드에서 오답노트와 함정 카드만 섞어 반복하고, 시험 당일 아침에는 요약노트를 단원별로 훑어본다.

## 4. 학습 콘텐츠 범위

콘텐츠는 이미 정리한 SQL 문법 요약 18개 단원과 정규식 메타문자 1개 단원, 총 19개 단원이며 약 420장의 카드로 만든다. 기준 DBMS는 Oracle이고, SQL Server 차이점은 별도 태그로 구분한다.

### 카드 유형

| 유형 | 앞면 | 뒷면(정답) | 예시 |
| --- | --- | --- | --- |
| 정의 카드 | 함수·연산자·기호 이름 | 정의 + 문법 + 예시 | NULLIF(a, b) → a = b이면 NULL, 다르면 a |
| 결과 예측 | SQL 식 또는 쿼리 | 결과값 + 해설 | SUBSTR('ABCDEF', -3, 2) → 'DE' |
| 빈칸 채우기 | 일부를 비운 문법 | 빈칸 정답 | CONNECT BY \_\_\_ empno = mgr → PRIOR |
| OX 함정 | 함정 진술 | O/X + 이유 | UNIQUE 제약은 NULL을 허용하지 않는다 → X |
| 객관식 | 문제 + 보기 4개 | 정답 번호 + 해설 | ROLLUP(A, B)가 만드는 그룹 수는? → 3 |
| 순서 배열 | 섞인 항목 | 올바른 순서 | SELECT 논리적 실행 순서 |
| DBMS 비교 | Oracle 문법 | SQL Server 대응 문법 | NVL → ISNULL |

각 카드는 원본 요약에서 ⚠️ 표시된 내용이면 `trap` 태그를, SQL Server 관련이면 `mssql` 태그를 갖는다.

### 콘텐츠 제작 방식

1. 두 요약 자료를 단원별 Markdown 원본으로 저장한다 (요약노트 화면에서 그대로 사용).
2. Claude로 원본을 8절의 JSON 스키마에 맞춰 카드로 변환한다. 결과 예측과 함정 카드를 우선 생성한다.
3. 결과값이 있는 카드는 Oracle 실행 환경(Oracle Live SQL 등)에서 샘플을 검증하고, 검증된 카드에 `verified: true`를 표시한다.
4. 학습 중 오류를 발견하면 카드에서 바로 "오류 신고" 메모를 남겨 나중에 일괄 수정한다.

### 주요 기능 상세

**F-02 플래시카드 학습**

- 카드 상단에 단원명, 카드 유형, 태그(⚠️ 함정, SQL Server)를 표시한다.
- 코드·SQL은 고정폭 글꼴과 구문 강조로 표시한다.
- 키보드 단축키를 지원한다: Space = 뒤집기, 1 = 틀림, 2 = 헷갈림, 3 = 맞힘.
- 모바일에서는 탭으로 뒤집고 좌/우 스와이프로 틀림/맞힘을 입력한다.
- 세션 종료 시 학습 수, 정답률, 새로 Box가 올라간 카드 수를 요약한다.

**F-09 퀴즈 모드**

- 출제 범위(단원, 전체), 문항 수(10/20/40), 카드 유형을 선택한다.
- 40문항 전체 범위 퀴즈는 실제 2과목 문항 수에 맞춘 "미니 모의고사"로 사용한다.
- 퀴즈 결과도 간격 반복 기록에 반영한다 (정답 = 맞힘, 오답 = 틀림).

**F-11 시험 모드**

- 11/11(D-3)부터 홈 화면에 시험 모드를 노출한다.
- 세션 구성 비율: 오답노트 40%, 함정 카드 30%, Box 1\~2 카드 30%.

## 6. 학습 알고리즘

복습 일정은 SM-2보다 구현과 이해가 쉬운 5단계 Leitner 박스로 정하고, 3주라는 짧은 기간에 맞춰 간격을 최대 7일로 압축한다.

### Leitner 박스 규칙

| Box | 의미 | 다음 복습 간격 | 맞힘 시 | 헷갈림 시 | 틀림 시 |
| --- | --- | --- | --- | --- | --- |
| 0 | 미학습 | — | Box 2 | Box 1 | Box 1 |
| 1 | 모름 | 같은 세션 안에서 재출제 후, 다음 날 | Box 2 | Box 1 | Box 1 |
| 2 | 익히는 중 | 1일 | Box 3 | 유지 | Box 1 |
| 3 | 대체로 앎 | 2일 | Box 4 | Box 2 | Box 1 |
| 4 | 앎 | 4일 | Box 5 | Box 3 | Box 1 |
| 5 | 완전 암기 | 7일 | 유지 | Box 3 | Box 1 |

- 처음 본 카드를 바로 맞히면 Box 2로 시작한다 (이미 아는 내용의 반복을 줄이기 위함).
- 같은 세션에서 재출제된 카드는 원래 Box 값과 무관하게, 맞혀도 해당 세션에서는 Box가 올라가지 않는다 (다음 날 이후 세션에서 평가해야 Box가 전진한다).
- 다음 복습일이 11/14(시험일)를 넘으면 11/13로 당긴다.

### 숙련도 산정

- 카드 숙련 여부: Box 3 이상이면 "숙련"으로 본다.
- 단원 숙련도(%) = 해당 단원의 숙련 카드 수 ÷ 단원 전체 카드 수 × 100
- 전체 숙련도는 단원 숙련도를 카드 수로 가중 평균한다.
- 함정 숙련도는 `trap` 카드만으로 같은 방식으로 계산한다.

### 오늘의 세션 구성

1. **복습 카드**: 다음 복습일이 오늘 이전인 카드를 모두 포함하고, 오래 밀린 카드와 낮은 Box 순으로 정렬한다.
2. **신규 카드 수**: 하루 신규 카드 = 남은 미학습 카드 수 ÷ (11/8까지 남은 학습일 수), 올림. 11/8까지 남은 학습일 수는 캘린더 일수 기준으로 오늘을 포함해 계산한다(11/8 − 오늘 + 1일, 0 이하면 1로 보정). 설정에서 상한(기본 40장)을 조정할 수 있다.
3. **신규 카드 순서**: 사용자가 고른 단원 우선, 그다음 출제 비중 "높음" 단원 순.
4. **세션 길이**: 기본 30장 단위로 끊고 "계속하기"로 이어간다 (20분 내외 목표).
5. **혼합 비율**: 복습 카드 2장마다 신규 카드 1장을 섞어 지루함을 줄인다.

### 오답노트 자동 수집 규칙

- 최근 7일 안에 "틀림"을 1회 이상 받은 카드, 또는 "헷갈림"을 2회 이상 받은 카드를 자동 추가한다.
- 연속 3회 "맞힘"이면 오답노트에서 자동으로 빠진다 (수동 추가 카드는 수동으로만 해제).

### 기본 흐름 (평일 복습)

1. 홈에서 "오늘의 복습 32장"을 누른다.
2. 학습 화면에서 카드를 보고 답을 떠올린 뒤 뒤집는다.
3. 자가평가 버튼을 누르면 Box와 다음 복습일이 즉시 저장되고 다음 카드로 넘어간다.
4. 30장이 끝나면 세션 결과 화면이 나오고, "계속하기" 또는 "홈으로"를 고른다.
5. 홈의 숙련도와 연속 학습일이 갱신된다.

- 모바일 우선(375px 기준)으로 설계하고 PC에서는 가운데 정렬된 카드 레이아웃을 쓴다.

## 8. 데이터 모델과 콘텐츠 스키마

콘텐츠(단원·카드)는 앱에 포함되는 정적 JSON 파일로, 학습 기록은 브라우저 IndexedDB에 분리해 저장한다. 콘텐츠를 수정해도 학습 기록은 카드 `id`로 연결되어 유지된다.

### 엔터티

| 엔터티 | 저장 위치 | 주요 필드 |
| --- | --- | --- |
| Unit | `content/units.json` | id, no, title, weight(high/mid/low), summaryFile |
| Card | `content/cards/unit-XX.json` | id, unitId, type, front, back, explanation, choices, answer, tags, verified |
| ReviewState | IndexedDB `reviewStates` | cardId, box, dueDate, lastReviewedAt, correctStreak, lapseCount, inWrongNote, manualWrongNote |
| ReviewLog | IndexedDB `reviewLogs` | id, cardId, reviewedAt, result(again/hard/good), mode(daily/quiz/exam), elapsedMs |
| CardNote | IndexedDB `cardNotes` | cardId, bookmarked, memo, errorReport |
| Settings | IndexedDB `settings` | examDate, newCardLimit, sessionSize, theme |

### 카드 JSON 예시

```json
[
  {
    "id": "u03-sub-002",
    "unitId": "u03",
    "type": "predict",
    "front": "SELECT SUBSTR('ABCDEF', -3, 2) FROM DUAL;",
    "back": "'DE'",
    "explanation": "시작 위치가 음수이면 뒤에서부터 센다. 뒤에서 3번째 'D'부터 2글자.",
    "tags": ["oracle"],
    "verified": true
  },
  {
    "id": "u02-notin-001",
    "unitId": "u02",
    "type": "ox",
    "front": "WHERE deptno NOT IN (10, NULL) 은 deptno가 10이 아닌 행을 조회한다.",
    "answer": "X",
    "explanation": "NOT IN 목록에 NULL이 있으면 deptno <> NULL 이 항상 UNKNOWN이므로 결과는 0건.",
    "tags": ["trap"],
    "verified": true
  },
  {
    "id": "u08-rollup-001",
    "unitId": "u08",
    "type": "choice",
    "front": "GROUP BY ROLLUP(A, B, C) 가 만드는 그룹 수는?",
    "choices": ["3", "4", "6", "8"],
    "answer": "2",
    "explanation": "ROLLUP 인자 n개 → n+1개 그룹: (A,B,C), (A,B), (A), ().",
    "tags": [],
    "verified": true
  }
]
```

- `type` 값: `definition`, `predict`, `cloze`, `ox`, `choice`, `order`, `dbms`
- `answer`는 `choice`에서 보기 인덱스(1부터), `ox`에서 "O"/"X", `order`에서 `items` 배열의 0부터 시작하는 인덱스로 이루어진 정답 순서 배열로 쓴다.
- `front`, `back`, `explanation`은 Markdown을 허용해 코드 블록과 표를 넣을 수 있다.
- 카드 `id`는 `u{단원번호}-{주제}-{일련번호}` 형식으로 고정하고, 내용을 고쳐도 바꾸지 않는다.

## 12. Android 스마트폰·PC 사용을 위한 배포와 설치

하나의 웹 코드를 PWA(Progressive Web App)로 배포해 Android에서는 홈 화면 앱으로, PC에서는 데스크톱 앱으로 설치해 쓴다. 앱 스토어 등록이나 네이티브 개발 없이 HTTPS 주소 하나로 두 기기를 모두 지원하므로 3주 일정에 맞는 유일한 방식이다.

### 배포 방식 비교

| 방식 | Android | PC | 추가 개발 | 결정 |
| --- | --- | --- | --- | --- |
| PWA (GitHub Pages 배포) | Chrome에서 "앱 설치" → 홈 화면 아이콘, 전체 화면 실행 | Chrome·Edge에서 설치 → 별도 창, 시작 메뉴 등록 | vite-plugin-pwa 설정 반나절 | **채택 (P0)** |
| TWA APK (PWABuilder) | APK 파일로 설치, 주소창 없는 앱 | 해당 없음 (PWA 그대로 사용) | PWA 완성 후 1\~2시간, 서명 키 관리 필요 | 필요 시 P2 |
| Capacitor 하이브리드 | APK 빌드 | 해당 없음 | Android Studio 설치·빌드 환경 구성 | 제외 |
| 네이티브 앱 (Kotlin 등) | 별도 개발 | 별도 개발 | 수 주 | 제외 |

### 전체 과정

1. **반응형 UI 구현**: 화면 폭 640px 미만은 하단 탭 + 스와이프 조작, 1024px 이상은 좌측 사이드바 + 키보드 단축키 레이아웃으로 만든다.
2. **PWA 구성**: Web App Manifest, 앱 아이콘, 서비스 워커(오프라인 캐시)를 vite-plugin-pwa로 설정한다.
3. **저장소와 자동 배포**: GitHub 저장소에 push하면 GitHub Actions가 빌드해 GitHub Pages(HTTPS)로 배포한다. Vite `base`는 `/저장소명/`으로 맞추고, 새로고침 시 404를 피하기 위해 라우터는 HashRouter를 쓴다.
4. **설치 가능성 검증**: PC Chrome 개발자 도구의 Application → Manifest 패널과 Lighthouse로 설치 조건(HTTPS, manifest, 서비스 워커, 아이콘)을 확인한다.
5. **Android 설치**: Android Chrome으로 배포 주소에 접속 → 메뉴(⋮) → "앱 설치" 또는 "홈 화면에 추가" → 홈 화면 아이콘으로 실행한다.
6. **PC 설치**: Chrome 또는 Edge로 접속 → 주소창 오른쪽 설치 아이콘 → "설치"를 누르면 별도 창으로 열리고 시작 메뉴·바탕화면에 바로가기가 생긴다.
7. **오프라인 확인**: 한 번 실행한 뒤 비행기 모드(Android)·네트워크 끊기(PC)에서 학습이 되는지 확인한다.
8. **업데이트**: 카드 수정 등 새 버전을 배포하면 앱 상단에 "새 버전이 있습니다 — 새로고침" 안내를 띄우고, 누르면 갱신한다. 학습 기록(IndexedDB)은 업데이트해도 유지된다.

| 아이콘 | 192×192, 512×512 PNG + 512×512 maskable(Android 원형 아이콘 대응), PC용 favicon |
| 서비스 워커 | 앱 화면(JS·CSS·HTML), 카드 JSON, 요약노트 Markdown을 모두 사전 캐시해 오프라인 동작 |
| 업데이트 방식 | 자동 교체가 아닌 사용자 확인 후 갱신 (학습 세션 중 화면이 바뀌지 않도록) |
| 저장소 보존 | 첫 실행 시 `navigator.storage.persist()`를 요청해 브라우저가 학습 기록을 임의로 지우지 않게 함 |
| 화면 | Android 상태 표시줄 색을 theme\_color로 맞추고, 안전 영역(노치) 여백 처리 |

### 기기 간 학습 기록 관리

학습 기록은 기기마다 따로 저장되므로, Android를 매일 복습용 주 기기로, PC를 요약노트 읽기·퀴즈·카드 검수용 보조 기기로 정한다. 두 기기 기록을 합칠 때는 JSON 백업을 쓴다.

- **내보내기**: 설정 → "학습 기록 내보내기". Android에서는 공유 시트(Web Share API)로 Google Drive나 카카오톡 "나에게 보내기"로 보내고, PC에서는 파일로 저장한다.
- **가져오기(병합)**: 카드별 기록은 `lastReviewedAt`이 더 최근인 쪽을 남기고, 학습 로그는 `id` 기준으로 합친다. 가져오기 전 현재 기록을 자동 백업한다.
- **자동 동기화(F-19, 선택)**: MVP를 1주 써 보고 수동 백업이 번거로우면 Firebase Firestore 무료 플랜 + Google 로그인으로 동기화를 추가한다. 도입하지 않으면 9절의 "서버 없음" 원칙을 유지한다.
